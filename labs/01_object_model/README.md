# L01｜看懂对象布局、虚函数和析构（约 4 小时）

本实验从已有的 [observe.cpp](observe.cpp) 开始。完成后，你应能解释：对象占了哪些字节、为什么有填充、虚函数如何选择实现、为什么析构会依次经过 Derived 和 Base。

下面按顺序做。普通成员函数实验不涉及 virtual；多继承和虚继承留到最后选做。材料入口在 [RESOURCES.md](../../docs/RESOURCES.md)：R01 是对象布局讲义，R14 的 C.35/C.67 用于检查析构和多态复制规则。

```sh
cd ~/quant-dev-interview-lab

cmake --build --preset debug --target object_model
./build/debug/object_model
```

调试时，在 observe.cpp 设置断点，按 F5，选择 object_model。

原程序用 require 检查日志数量和顺序。require 条件不成立会抛异常；当前 main 没有捕获它，因此进程会终止。新增实验可以写在 main 的原日志打印循环之后；涉及构造/析构记录时，用另一份日志容器，避免改变原程序预期的五条日志。不要仅靠修改计数来掩盖析构错误。

## 第一步：理解现有程序中的三个对象

**要做什么：**先阅读源文件，分别找出堆上的 Derived 对象、它内部的 Base 子对象，以及局部变量 sliced。说明 object 是拥有堆对象的智能指针，sliced 则是另一个独立对象。

**先预测：**
- Base 构造函数初始化 construction_value_ 时调用 value，应该得到什么？
- 构造完成后，通过 object 调用 value，应该得到什么？
- sliced 的类型是什么？调用它的 value 应该得到什么？

**运行后检查：**这三个值分别是 1、2、1。解释原因时分别使用“构造阶段”“动态派发”“对象切片”，不要只记住数字。

原日志的含义如下：

| 日志 | 对应哪个对象 |
|---|---|
| Base constructor | 堆上 Derived 的 Base 部分正在构造 |
| Derived constructor | 堆上 Derived 的派生部分正在构造 |
| Base destructor | 独立的局部对象 sliced 正在析构 |
| Derived destructor | 智能指针开始销毁堆上的 Derived |
| Base destructor | 同一个 Derived 内部的 Base 部分正在析构 |

sliced 使用 Base 的拷贝构造函数；当前默认拷贝构造没有记录日志，因此日志中没有它的构造条目。

**完成标准：**能给每一条日志指出对象身份。说明局部对象按构造完成顺序的逆序析构，而一个派生对象内部又按“派生部分、基类部分”清理。

## 第二步：解释 sizeof 和 alignof

**术语：**
- sizeof：一个对象本身占用的总字节数，包括填充；不包含成员函数代码，也不包含它引用的其他对象。
- alignof：对象起始地址需要满足的对齐要求。例如 8 字节对齐意味着地址应是 8 的倍数。
- padding：编译器为了满足对齐要求，在成员之间或对象尾部保留的填充字节。
- vptr：对象中用于定位虚表的指针；具体布局属于编译器和平台实现。

**要做什么：**运行原程序，记录 Plain、Base、Derived 的大小和对齐。画出 Base 各部分的位置。

当前这台 Mac 上，Base 的布局为：

| 偏移 | 内容 | 大小 |
|---|---|---|
| 0–7 | 虚表指针 | 8 字节 |
| 8–15 | 引用成员 events_ 的存储 | 8 字节 |
| 16–19 | 整数 construction_value_ | 4 字节 |
| 20–23 | 尾部 padding | 4 字节 |

events_ 引用的 vector 存放在别处。Derived 没有额外数据成员，当前大小与 Base 相同。

**完成标准：**解释为什么实际成员存储合计 20 字节，却得到 sizeof(Base)=24；指出这些数字是本机观察，不是所有 C++ 平台的统一规定。

## 第三步：交换两个成员的声明顺序

**要做什么：**
1. 定义普通类型 A，先声明一个 char 成员 c，再声明一个 int 成员 x。
2. 定义普通类型 B，先声明 int 成员 x，再声明 char 成员 c。
3. 输出两个类型的 sizeof 和 alignof，稍后用第五步的工具查看成员偏移。

“交换字段顺序”指的是改变类定义中的声明顺序，不是在运行时交换 c 和 x 的值。

当前 Mac 上，char 占 1 字节，int 占 4 字节且按 4 字节对齐。因此你会看到：

| 类型 | 从低地址到高地址的布局 | 总大小 |
|---|---|---|
| A | char：1 字节 → padding：3 字节 → int：4 字节 | 8 字节 |
| B | int：4 字节 → char：1 字节 → 尾部 padding：3 字节 | 8 字节 |

**交换顺序不一定改变总大小。** 这个例子的重点是观察填充从成员之间移到了对象尾部。尾部补齐能保证数组中的下一个对象也正确对齐。

**再做一个小变化：**给 A 添加一个非虚成员函数，取名 hello，返回类型为 void，无参数，函数体为空。再次打印 sizeof(A)。它应保持不变，因为函数代码不存放在每个对象内部。这里“非虚”就是没有声明 virtual。

**完成标准：**指出填充所在位置，并解释为什么增加普通成员函数不增加对象大小。

**选做：**比较三个成员的两种顺序：“char、int、char”和“int、char、char”。本机大小分别为 12 和 8 字节。用同样的对齐规则解释差异。

## 第四步：通过 Base 引用观察动态派发

**要做什么：**
1. 写一个名叫 dispatch 的普通函数。它返回 int，接收一个 Base 引用作为参数。
2. 函数内部调用这个参数的 value，并把结果返回。
3. 分别传入一个独立 Base 对象和一个 Derived 对象，打印返回结果。
4. 再定义一个直接继承 Base 的派生类，让它覆盖 value 并返回 3。把它也传给同一个 dispatch。

**Base 引用是参数类型，不是返回类型。** dispatch 只是函数名字，意为“派发”，不是 C++ 关键字。现有 Derived 声明为 final，所以第二个派生类应直接继承 Base。

引用不会复制对象，因此传入 Derived 时不会发生切片。三个对象应分别得到 1、2、3。

**观察问题：**dispatch 的参数类型始终是 Base 引用，为什么结果还能随实际对象变化？画出“对象 → vptr → 对应函数槽位 → 函数入口”的路径。

**完成标准：**能区分参数的静态类型与实际对象的类型，并解释引用传参与复制成 Base 对象的不同结果。

## 第五步：用工具核对布局和调用

先查看成员布局：

```sh
clang++ -std=c++20 -Iinclude -Xclang -fdump-record-layouts -fsyntax-only labs/01_object_model/observe.cpp > build/object_layout.txt 2>&1
```

打开 build/object_layout.txt，搜索 Base、Derived、A、B 的类布局。每行左侧数字是成员相对于对象起点的字节偏移；只看这些类型，不必读完标准库的布局。

再分别导出无优化和优化后的汇编：

```sh
clang++ -std=c++20 -Iinclude -O0 -S labs/01_object_model/observe.cpp -o build/object_model_O0.s
clang++ -std=c++20 -Iinclude -O2 -S labs/01_object_model/observe.cpp -o build/object_model_O2.s
```

在汇编中搜索 dispatch，比较函数本身和它的调用位置：

- 间接调用：先读取虚表里的函数地址，再跳到该地址。本机 ARM64 常见指令是 blr。
- 直接调用：目标函数已经确定，本机常见指令是 bl。
- 内联：函数体被放进调用位置，可能看不到独立的调用指令。

“去虚化”指编译器能够确定实际目标，从而把虚调用改成直接调用或进一步内联。O2 不保证每个虚调用都去虚化；参数的实际类型能否被确定、是否内联等都会影响结果。

**完成标准：**找出一处实际调用，说明它属于哪种情况。函数名在汇编中可能经过编码；搜索 dispatch 这个词即可帮助定位，不必先背编码规则。

## 最后自测

- 能区分虚表、对象里的 vptr，以及 RTTI 指针的用途。
- 能解释 Base 构造期间为何调用 Base 的实现，构造完成后为何能派发到 Derived。
- 能解释通过 Base 指针删除时，虚析构如何选择入口，以及随后为何自动析构 Base 部分。
- 能区分 D0（完整析构并释放存储）、D1（完整析构）、D2（基类子对象析构，排除虚基类）；当前例子没有虚继承，D1/D2 的清理效果相同。
- 能画出 padding，解释字段顺序和成员函数怎样影响对象大小。
- 能说明观察到的一次布局或汇编结果，与 C++ 语言保证有什么区别。

删除虚析构后的基类指针删除属于未定义行为；即使某次日志看似正常，也不能据此判断正确。默认实验保留正确的虚析构路径。

多继承选做：让一个类型继承两个接口，分别取得指向这两个基类部分的指针并比较地址，观察是否需要调整。完成单继承实验后再做；虚继承不计入本次必做任务。
